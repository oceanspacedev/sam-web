CRITICAL: Organizational Scope Cascading

When a user is assigned to ANY level in the hierarchy, they automatically get access to ALL DESCENDANT levels. Example: Division access includes all Regions and Clusters under that Division.

03

Role-Based Access Control

Scope Level Filter By Cascade Access Example
all No filtering Full system access Super Admin sees all data
badanusaha user_badan_usaha → Division → Region → Cluster Manager sees entire business unit
divisi user_divisi → Region → Cluster Division Head sees division + descendants
region user_regions → Cluster Region Manager sees region + clusters
cluster user_clusters None (leaf node) Sales rep sees assigned clusters only 
// HasOrganizationalScope Trait - Applied to all models
public function scopeWithOrganizationalAccess($query, $user)
{
    $scope = $user->role->organizational_scope_level;

    if ($scope === 'all') {
        return $query;
    }

    $orgIds = $user->getOrganizationalIds(); // Cached IDs

    return $query->where(function($q) use ($orgIds, $scope) {
        switch($scope) {
            case 'badanusaha':
                $q->whereIn('badan_usaha_id', $orgIds['badanusaha']);
                break;
            case 'divisi':
                $q->whereIn('division_id', $orgIds['division']);
                break;
            // ... other scopes
        }
    });
}
04

LEAD/NOO Data Flow

1

Create LEAD

Submit new potential outlet with minimal requirements. No KTP needed at this stage.

POST /api/registers/leads
2

Upgrade LEAD → NOO

Add KTP documentation and complete required fields to upgrade to NOO status.

PATCH /api/registers/{id}/upgrade
3

Confirm NOO

Set outlet code and credit limit. Ready for approval.

PATCH /api/registers/{id}/confirm
4

Approve/Reject NOO

Final decision. Approval creates Outlet record. Rejection marks with reason.

PATCH /api/registers/{id}/approve
PATCH /api/registers/{id}/reject
5

Outlet Created (Automatic)

On approval, Outlet record is automatically created with data from NOO.

// Handled by Register model logic
05

Visit Management Flow

1

Plan Visit

Create scheduled visits to Outlet or Register (LEAD/NOO) targets.

POST /api/plan-visits
2

Check-in

Start visit with photo proof and GPS location. Creates Visit record.

POST /api/visits/checkin
3

Check-out

End visit with photo proof. Updates Visit record with end time.

POST /api/visits/{id}/checkout
4

Monitor Visits

Track active visits and visit history for supervision.

GET /api/visits/monitor

POLYMORPHIC RELATIONSHIPS

Both Visit and PlanVisit use polymorphic visitable relationship that can target either Outlet or Register models. This enables unified visit management across different target types.
